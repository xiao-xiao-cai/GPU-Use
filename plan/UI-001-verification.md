# UI-001 界面改版验收记录

浏览器检查使用 Vite 生产构建和虚拟项目。复测时先执行：

```sh
npm --prefix frontend ci
npm --prefix frontend run typecheck
npm --prefix frontend run build
python3 frontend/tests/ui001_fixture.py frontend/dist
```

在 Chrome 打开 `http://127.0.0.1:4178/`。用新的浏览器上下文复测登录，使用虚拟账号 `demo` 和密码 `demo`。

## 阶段一 · 导航、主题与登录

- Node.js 22.22.3 下从本阶段的 Git 暂存快照执行干净安装、类型检查和生产构建，全部通过。锁定 Element Plus 2.14.8 和图标 2.3.2，按官方指南用 Vite 插件与 ElementPlusResolver 自动按需导入组件及 CSS。
- `?scenario=login` 从密码框按 Enter 后进入实例总览。 `?scenario=expired` 在受保护的接口返回 401 时恢复带过期提示的登录表单。
- `?scenario=uninitialized` 显示现有管理员初始化命令和检查入口。 `?scenario=unreachable` 显示服务错误和重新连接按钮。
- 窄屏用 Enter 打开导航抽屉，四个导航链接均有可访问名称。用 Escape 关闭后，焦点回到打开菜单按钮。

## 阶段二 · 实例总览、详情和监控

总览样本为两台运行且有卡的实例、一台关机实例、一条待核对记录和一项即将执行的任务。Chrome 视口坐标由 `getBoundingClientRect()` 读取，单位为 CSS 像素。

| 视口 | 卡片列数 | JupyterLab 顶边／底边 | SSH 顶边／底边 |
| --- | ---: | ---: | ---: |
| 1440 × 900 | 3 | 430.69／474.69 | 430.69／474.69 |
| 1024 × 768 | 2 | 430.69／474.69 | 430.69／474.69 |
| 390 × 844 | 1 | 436.39／480.39 | 436.39／480.39 |
| 320 × 700 | 1 | 436.39／480.39 | 436.39／480.39 |

- 总览在 320 像素下测试了 98 字长名称和键盘筛选，无页面横向溢出。清单返回焦点恢复到原卡片。A 项目迟到结果未覆盖 B，切回 A 恢复筛选。
- JupyterLab 正常、未配置、关机、过期分别显示对应入口或原因。模拟剪贴板失败时，手动命令获得焦点并可全选。刷新失败保留上次快照，空项目有效零值正常显示。
- 打开 `?scenario=detail#instances?project=sample&instance=train-a` 验证了两卡监控中 GPU 0 的 0% 和 GPU 1 的断点。切换详情页签保留选卡及缩放，“回到最新”将缩放从 20–80% 恢复为 0–100%。
- 浏览器设为 America/Los_Angeles。从现有预约选择替换时，北京时间 2026-11-21 06:21 发送 Unix 秒值 1795213260，携带 `conflict=replace`。用 Esc 关闭正在读取 SSH 密码的对话框可中止请求、清空内容并恢复触发按钮焦点。
- 实例详情验证了抢占式实例隐藏预约、密钥登录不查询密码、只读／恢复核对／在途阻止操作。键盘打开“更多操作”，重启确认显示实例与训练影响，关闭后恢复触发焦点。模拟预约从已排队推进至成功。
- 本阶段暂存快照通过类型检查和生产构建。Chrome 网络资源表显示首次总览只加载入口与任务提示；首次进入实例详情的监控页签才加载实例详情、MetricChart 与 chart-renderer 独立资源。

## 阶段三 · 库存、任务编辑和运行回执

- 本阶段暂存快照通过类型检查和生产构建。Chrome 用虚拟库存在桌面和 320 × 700 检查了默认关注页、目录筛选、规格展开、分批加载、历史、添加／取消关注、无项目浏览和读取失败后重试。
- 在 320 × 700 的生产构建中，从目录创建 A100 模板并在任务编辑中引用，预览请求保留了项目、按顺序保存的可用区、模板 ID 与版本。六类任务的预览均得到 200 回执；实例操作携带目标实例 ID，采购携带原精度报价。
- 在 `?scenario=preview-race#tasks` 将采购预算从 5 改为 6.000125。返回编辑时旧预览请求被取消，保存前取得新预览，两次点击只产生一个创建请求。另模拟首次预览 503，同一草稿就地重试成功。
- 任务操作菜单验证了编辑、暂停、恢复、立即执行，并从提交进入已排队的运行回执。关闭编辑后焦点回到原任务的操作按钮。采购待核对从异常入口打开，验证了停止后续尝试后继续查看回执、提交绑定说明及确认未成交后释放预留。
- 通过 Enter 打开运行抽屉，用 Esc 关闭后恢复“查看运行”焦点。直接运行链接支持刷新与前进后退，项目不匹配或运行不存在时显示具体原因。

## 阶段四 · 后台状态、设置及跨页回归

- 本阶段暂存快照通过类型检查和生产构建。Chrome 在 320 × 700 和 1440 × 900 检查了后台状态、配置表单与通知列表。移动端可展开记录查看投递原因和时间，页面无横向溢出。
- `?scenario=settings#settings` 显示过期心跳及规格检测超时。采集频率超范围时聚焦输入框且未提交，双击保存仅发送一个 PATCH。输入 99 后等到下一次后台刷新，未保存值仍为 99。 `?scenario=settings-error#settings` 返回 422 后保留表单输入。
- 同一事件的三个渠道显示站内未读、飞书投递失败和邮件已送达。飞书重试只将飞书改为等待投递，标为已读只改变站内消息。测试消息将列表限定在返回的事件编号并聚焦投递记录，清除事件后可查全部记录。
- 清理旧原生控件和列表样式后，再次检查 320 × 700 总览截图。首卡两个按钮的底边均为 480.39 px，高度 44 px，文档滚动宽度等于可用宽度。总览初载未请求 ECharts，进入监控后加载独立图表资源，切换规格页签后返回沿用原画布。
- 云端操作、回执、站内及外部通知均在本地虚拟 API 中验证。
