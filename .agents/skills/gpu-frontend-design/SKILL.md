# 前端设计与交互评审

## 从任务到页面

1. 写出用户打开页面要做的判断、能采取的主要行动、行动后的可见结果。进入已有页面时先核对现有导航、组件和设计用词。
2. 区分页面状态、组件临时状态和服务端事实。为每个编辑值和查询条件指定一个所有者。决定哪些筛选需要保留在地址或页面级状态中。
3. 定义视觉层级。先突出面向任务的结果、受影响对象和主操作，再放数据时间与细节。用一致的间距、字体层级和交互样式。给危险或有费用的操作清楚的对象、后果和反馈。
4. 为首载、正常、空结果、部分数据、过期、网络失败、操作执行中和最终结果选择实际可达的状态。每个状态说明用户能看到的文字、可用操作和恢复入口。
5. 说明窄屏阅读顺序、列折叠方式和主要操作位置。键盘可完成筛选、打开并关闭弹窗，关闭后焦点回到触发处。状态用文本或形状配合颜色，图表提供文字摘要。

仅在改动涉及实时曲线、采样新鲜度或多卡对比时读取 [图表与状态评审规则](references/charts-and-status.md)。

## 业务逻辑的调用链

从改动的真实入口沿调用方、共享类型及 API 追到结果的消费者。写下每个受影响环节的输入、输出、状态所有者及失败由谁处理。局部展示改动只说明相关字段。跨层契约或后台状态变化衔接 `gpu-backend-design`，组件选型衔接 `gpu-element-plus`。

| 从库存规格生成任务 | 设计时核对的边界 |
| --- | --- |
| 目录规格 → 模板 | 从 `InventoryPage.vue` 的 `saveSpec()` 追到 `POST /api/templates`。规格中的地域与可用区写入 `config.zones`，服务端按项目保存并返回模板 ID 和版本 |
| 模板 → 任务草稿 | `TaskPage.vue` 的 `selectTemplate()` 选择引用的模板，`detachTemplate()` 允许独立编辑复制的规格。编辑页持有预算与预约时间，`draft()` 输出 `TaskDraft`，引用模式同时携带模板 ID 和版本 |
| 草稿 → 预览 → 保存 | `previewTask()` 提交到 `POST /api/tasks/preview`，`TaskStore.preview()` 按项目实例快照、模板版本及预算生成预览。核对预算或模板变化后旧预览立即失效，`saveTask()` 只将已预览的当前草稿交给创建或更新接口 |
| 任务触发 → 运行 → 回读 | `enqueue_trigger()` 将本次配置写入运行快照，worker 推进运行状态。`loadRun()` 从 `GET /api/runs/{run_id}` 读回回执，核对所属项目后更新选中记录 |

交给实现者时，列明改预算涉及的消费者、谁负责丢弃迟到预览，以及哪些已排队运行继续使用原快照。如果改动也涉及布局，补充桌面和手机的主操作位置及验证入口。

## 小型设计交付示例

| 用户任务 | 状态所有者 | 可验证的交互 |
| --- | --- | --- |
| 在实例详情比较两张卡的利用率 | 页面保存时间范围与选中的卡，服务端提供带采样时间的数据 | 用户缩放到十分钟窗口后自动刷新，时间范围和卡选择保持 |
| 查看刷新失败的库存页 | 查询状态与上次成功快照分别保存 | 页面显示上次成功时间和重试入口，旧值有明确标记 |

给出本次改动的页面结构、组件边界、状态表及桌面和手机的验收场景。小改动只写受影响的部分。已有页面可通过浏览器核对交互时，使用根规则指定的浏览器流程。

## Gotchas

- 空列表、加载中和采集失败是三种结果。首次加载的占位形态不要替代错误反馈。
- 用户切换项目、实例或时间范围后，旧请求返回的数据不能覆盖新视图。
- 后台已接收请求与云端操作完成要有各自的反馈。缺少终态时给出继续查看的入口。
