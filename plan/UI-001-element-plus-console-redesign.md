# UI-001 · GPU 实验管理台 Element Plus 界面改版计划

| 项目 | 约定 |
| --- | --- |
| 使用者 | 通过受信任网络管理实验的个人用户，电脑负责日常操作，手机用于巡检和快速连接 |
| 首要目标 | 找到目标实例，确认运行及有卡状态，直接打开 JupyterLab 或复制 SSH 命令 |
| 设计决定 | 浅色工作区配深色导航，JupyterLab 为主操作，创建和编辑任务采用三步流程 |
| 现状基线 | 前端 0.3.0，提交 `87b5f39`。基线来自本地构建产物与虚拟数据，改版验收待实施 |

## 1. 现状与衡量方法

现版有四个一级入口。总览已经提供两项连接操作，但卡片先列计算规格、可用区和计费，再显示连接按钮。详情页把常用连接和六类实例操作放在相邻区域。任务中心将配置表单、运行回执和两个列表叠在同一页，预览后要在长页面里来回找字段。[应用入口](../frontend/src/App.vue) · [实例总览](../frontend/src/pages/InstancePage.vue) · [任务中心](../frontend/src/pages/TaskPage.vue)

基线样本为同一项目的两台运行实例、一台已关机实例、一条待人工核对的运行记录和一项即将执行的任务。首台实例有新鲜快照、有效的 JupyterLab 地址与 SSH 命令。以下坐标均从视口顶部向下计算，单位为 CSS 像素。

| 视口 | 现版测量 | 改版通过条件 |
| --- | --- | --- |
| 1440×900 | 网格分为四列，每列约 286 像素宽，第四列留空。首卡 JupyterLab 按钮顶边为 619，SSH 为 666 | 三卡填满一行，首卡两个按钮顶边差不超过 1 像素 |
| 390×844 | 首卡 JupyterLab 按钮顶边为 789，底边为 828 | 首卡两个连接按钮的底边均不超过 560，两者的触控高度均至少为 44 |
| 320×700 | 首卡 JupyterLab 和 SSH 按钮顶边分别为 837 和 883 | 两个按钮完整出现在首屏，页面无整体横向滚动 |

复测沿用上述数据顺序和简短名称，浏览器缩放 100%，模拟视口使用覆盖式或隐藏滚动条。打开实例总览、清空筛选，等待三张卡和两条任务提示出现，页面滚动到顶部。用 `getBoundingClientRect()` 读取两个可见控件的边界，同时核对截图与键盘操作。另在 1024×768 检查中等宽度的列数和页签布局。

## 2. 信息架构与视觉规范

| 优先级 | 用户想判断什么 | 在哪儿行动 |
| --- | --- | --- |
| 首要 | 哪台实例适合进入，如何连接 | 首屏的实例名称、运行及有卡状态、GPU 型号与张数、JupyterLab 主按钮和 SSH 次按钮 |
| 需要及时处理 | 训练是否即将中断，哪项运行需要核对 | 关机时间紧邻对应实例，待处理异常提供原因和“查看运行”入口。普通下一次任务用一行摘要 |
| 按需查看 | 如何比较资源、预约操作、检查投递或修改配置 | 实例详情、GPU 库存、任务中心、设置与通知。每个入口有明确的返回路径 |

### 2.2 布局、字级与操作样式

- **响应式**。宽屏使用约 208 像素的侧栏。中等宽度将其收成带可访问名称的图标栏，低于 768 像素改用菜单抽屉。桌面卡片按可用内容宽度排两至三列，建议最小列宽 340 像素，空轨道自动折叠。手机固定单列。列表中名称与状态始终可见，次要列放入展开区。
- **颜色和文字**。沿用深青导航 `#112732`、青绿主色 `#006B62`、白色面板与浅灰绿背景。正文 14–16 像素，区块标题 18–20 像素，页标题 24–28 像素。正文沿用现有中西文字体栈，ID、命令和数值使用等宽字体。普通正文对背景的对比度至少 4.5∶1。
- **间距和反馈**。采用 4、8、12、16、24、32 像素间距。每个操作区突出一个主动作，辅助动作使用描边按钮或文字链接。红色用于失败和破坏性确认，琥珀色用于过期和待核对，配合文字、图标及可见焦点。复制成功用就地短提示，持续失败保留原因和恢复入口。

## 3. 六个页面的交互设计

| 页面 | 首屏判断与主操作 | 次要内容与 Element Plus 组件 |
| --- | --- | --- |
| 登录 | 先确认会话状态。已初始化时可输入账号、密码并按 Enter 登录 | `ElForm`、`ElInput`、`ElButton`。首次检查用占位态，连接失败显示“重新连接”，未初始化展示现有管理员初始化命令，会话过期后回到登录表单 |
| 实例总览 | 默认入口。名称链接到详情，卡片直接打开 JupyterLab 或复制 SSH 命令。搜索作用于名称和 ID | `ElCard`、`ElTag`、`ElInput`、`ElSelect`。同步和异常提示位于清单上方。首次同步、项目无实例、筛选无匹配分别提示“等待同步”“同步实例”“清除筛选” |
| 实例详情 | 顶部显示名称、运行状态、关机预约和快速连接。运行时突出 JupyterLab，已关机且允许操作时突出“有卡开机” | `ElTabs` 分为“资源监控”“规格与网络”“生命周期与记录”。自定义 JupyterLab 地址、其他应用、磁盘、镜像、计费与近期操作保留入口。预约时间就近编辑，重启、立即关机和重命名收入 `ElDropdown`，沿用对应的确认或编辑对话框 |
| GPU 库存 | 默认展示“规格关注”的检测结果和最近成功时间。“机型目录”优先按 GPU 型号、地域、可用区筛选，从结果关注规格或存为模板 | `ElTabs`、`ElTable`、`ElCollapse`。GPU 张数、CPU、内存、平台及实例类型归入高级筛选。保留规格组合展开、分批显示和检测历史。未选择项目时仍可浏览目录，关注和保存模板提示先选择项目 |
| 任务中心 | 默认显示任务列表和“创建任务”。近期异常直达回执。“运行记录”另设页签，点选记录打开详情抽屉 | `ElSteps`、`ElForm`、`ElTable`、`ElDrawer`。编辑复用创建流程。保留立即执行、暂停、恢复、取消及按任务查看记录。待人工核对时先展示原因和可用操作，完整回执按需展开 |
| 设置与通知 | 默认打开“后台状态”，看 worker 心跳与各项最近成功时间。另设“采集与提醒”“通知与投递” | `ElDescriptions`、`ElForm`、`ElTabs`、`ElTable`。保存时提供字段错误和结果反馈。测试消息按事件定位，站内显示已读状态，飞书与邮件分别显示投递状态及失败重试 |

### 3.1 连接和监控的可用条件

- 当实例运行、快照新鲜、地址通过现有链接校验时，JupyterLab 使用可在新标签页打开的链接。无地址、快照过期和实例已关机分别显示配置、同步或开机提示。SSH 命令存在即可复制，复制失败提供手动选择命令的路径。
- “已确认有卡”计入快照新鲜、运行中且明确报告有卡的实例。快照过期时该统计显示“待同步”，卡片保留上次状态与时间。有效的零值正常显示为 0。
- 查看 SSH 密码沿用按需请求，密钥登录实例按现有登录方式展示。关闭弹窗或切换实例时中止未完成的密码请求并清空显示值。关机、重启确认框写明实例及对训练的影响。已存在云端关机预约时展示原时间和保留或替换的选项。
- 采样曲线继续使用 ECharts。显示选定指标、单位、时间范围、最近采样时间和每条序列的文字摘要。零利用率显示 0%，缺样显示断点。自动刷新保留卡选择与历史缩放，“回到最新”恢复跟随。首次展开页签或改变宽度时按可见容器重新测量图表。[监控组件](../frontend/src/components/MetricChart.vue)

### 3.2 创建与编辑任务

```mermaid
flowchart LR
  L["任务列表"] --> A["① 对象与规格"]
  A --> B["② 安排与通知"]
  B -->|获取服务端预览| C["③ 预览与确认"]
  C -->|修改安排| B
  B -->|修改对象| A
  C -->|当前草稿与预览一致| D["保存任务"]
  D --> L
```

1. **对象与规格**。选择现有六类任务中的一类，仅展示该类所需字段。已有实例操作选定目标，新建或库存检测展示规格及有序可用区。按模板获取实例时显示报价上限、购买次数和已有匹配实例时的处理方式。模板引用和“复制规格到任务”具有不同的后续更新行为，界面说明当前采用哪一种。
2. **安排与通知**。选择周期、北京时间、执行窗口、通知事件和渠道。按任务类型显示关联关机时间、登记截止或收件地址。上一步和下一步共享同一份草稿，校验错误定位到字段。手机采用单列，当页底部保留步骤操作。
3. **预览与保存**。调用现有服务端预览，展示下次执行、截止时间、匹配实例及适用的预算和模板版本。获取预览失败可就地重试。修改任一提交字段后，旧预览立即失效。只接受与当前草稿一致的预览结果。保存成功返回列表，运行是否完成以运行详情回执为准。

## 4. 接入、状态和兼容性

- **依赖与样式**。在现有 Vue 3、TypeScript、Vite 工程中用 npm 添加 `element-plus` 和 `@element-plus/icons-vue`，更新同一份前端锁文件。组件、图标与对应 CSS 按需引入，根部 `ElConfigProvider` 使用简体中文。通过主题变量定义主色、悬停、焦点及边框。随页面迁移收窄现有原生 `button`、`input`、`select` 选择器，保留页面和图表的异步加载。[前端清单](../frontend/package.json) · [官方快速入门](https://element-plus.org/en-US/guide/quickstart.html) · [主题变量](https://element-plus.org/en-US/guide/theming.html) · [国际化](https://element-plus.org/en-US/guide/i18n.html)
- **导航与状态归属**。沿用现有 hash 导航和 HTTP API。地址管理实例与运行深链接，如 `#instances?project=sample&instance=train-a` 和 `#tasks?run=sample-run`。应用层保存当前项目及按项目区分的总览筛选，页面管理库存条件、任务草稿、选中指标与时间范围，组件管理抽屉、弹窗和临时复制反馈。前进、后退、刷新深链接均可到达对应内容，返回清单时焦点回到来源卡片或列表标题。
- **数据与表单**。服务端提供状态、成功时间和执行回执。切换项目、实例或时间范围时取消或忽略旧请求。项目选择器直接接收组件值，表单保留原字段约束和提交行为。日期选择器用北京时间的输入值与现有时间转换函数衔接，提交 Unix 秒值。保留现有请求标识、会话处理和只读、恢复核对、在途操作的判断。[API 类型及客户端](../frontend/src/api/client.ts) · [快照与时间显示](../frontend/src/display.ts)
- **辅助操作**。菜单、筛选、页签、表单和弹层均可用键盘完成。对话框提供清晰标题，关闭后恢复触发处焦点。抽屉改为手机全宽后仍可关闭，工具提示之外保留禁用原因。沿用原生链接语义，使实例名称和 JupyterLab 支持浏览器的常规打开方式。[设计原则](https://element-plus.org/en-US/guide/design.html) · [组件目录](https://element-plus.org/en-US/component/overview.html) · [表单可访问性](https://element-plus.org/en-US/component/form.html#accessibility)

| 状态 | 用户看到的结果 | 恢复或后续动作 |
| --- | --- | --- |
| 首载、等待首次同步 | 请求期间使用骨架屏。请求成功但尚无成功快照时显示等待提示，首次读取失败时显示错误，数量和时间显示占位 | 读取失败可重试。可请求后台同步，收到受理回执后显示“已请求同步” |
| 空项目、清单为空、筛选无匹配 | 分别提示选择或同步项目、此项目暂无资源、当前筛选无匹配 | 保留同步入口，筛选无匹配时提供清除条件 |
| 部分字段缺失、刷新失败或采样过期 | 缺字段就地显示“未知”。保留上次成功数据与时间，标记有卡状态待确认和采样断点 | 在对应区域重试。机型目录的“可售”和具体规格的“当前可开／资源不足／未知”各自取自对应接口，布尔可用性只显示检测结论 |
| 只读、恢复核对、操作在途 | 在受影响的操作旁显示原因。运行详情可看到已排队、待核对、成功或失败 | 有运行编号时可查看回执，可重试时保留原请求语义 |
| 本地反馈与后台结果 | 复制成功、设置已保存、任务已提交、通知已排队各用对应措辞 | 操作失败保留输入，通知按渠道查看实际投递结果 |

## 5. 实施顺序与回归验收

| 顺序 | 实施内容 | 完成该阶段的证据 |
| --- | --- | --- |
| 1 | Element Plus、主题、导航、项目选择、登录和反馈模式 | 会话正常、过期、未初始化、后台暂不可达时均有可用入口。键盘可登录、切换菜单和关闭手机抽屉 |
| 2 | 总览、详情、快速连接和监控页签 | 复测第 1 节三个视口并记录数值。核对中等宽度、长名称和多卡。JupyterLab 可用、未配置、过期、SSH 复制失败、图表零值与断采均有对应表现 |
| 3 | 库存关注与模板、任务列表、三步编辑、运行记录和人工核对 | 从目录建立模板并用于任务。对“仅通知有货、只启动已有实例、按模板获取实例、关机、云端定时关机、巡检”逐类预览。修改预算后必须重新预览，重复点击保存只提交一次 |
| 4 | 后台状态、采集配置、通知投递、跨页回归及旧样式清理 | 草稿不被后台刷新覆盖。测试消息可定位到事件，失败渠道可单独重试。浏览器前进后退、异步图表加载、桌面与手机布局均有实际入口记录 |

跨阶段检查使用虚拟项目和响应，可从浏览器实际入口复现以下情景。

- **筛选与深链接**。在项目 A 搜索实例，进入详情后返回，再切换到项目 B。原卡片焦点与各项目筛选正确，迟到的 A 响应只影响 A。直接打开实例或运行链接，核对对象归属。对缺失对象给出原因和返回入口。
- **时间与云端操作**。在非东八区的浏览器中输入预约，预览与回执仍按同一北京时间显示。测试已有关机预约、抢占式实例、只读、恢复核对与模拟在途操作。确认显示对象、影响和禁用原因，记录从提交到终态的变化。
- **采购回执待核对**。模拟已提交而成交结果未知的运行，从异常入口查看原因，保留“停止后续尝试”“绑定已核实实例”和“确认未成交并释放预留”各自的适用条件。提交核对说明后查看回执，停止后续尝试时仍能跟踪已提交的云端请求。
- **监控与通知**。用两张卡的序列制造单卡断采，再恢复采样，检查文字摘要和缩放。在同一事件中模拟站内可读、飞书失败、邮件送达，重试飞书后其余渠道保留各自结果。

每个前端实施阶段运行类型检查和生产构建。依赖或锁文件变更后先执行干净安装。通过浏览器网络面板核对首次进入总览及首次进入监控页签的资源加载，记录视口、样本状态和实测差异。从仓库根目录执行以下命令，Node.js 版本要求为 22.12.0 或更高。

```sh
npm --prefix frontend ci
npm --prefix frontend run typecheck
npm --prefix frontend run build
```

本计划的文档验收项为唯一编号、六页设计、两幅总览线框、三步任务流程、可访问性、组件来源与可复测指标。改版测量和本地模拟回归见[分阶段验收记录](UI-001-verification.md)。
