# 成本日报预汇总实施方案

## 数据与计算

- SQLite 按项目、实例、北京时间日期保存成本日报。存储未舍入的金额、用量和可评估算力费等累计量。查询跨天或跨实例时先分别累计，再计算占比和单位费用。
- 采集继续按现有频率写入观测区间。新增区间只标记受影响的实例和日期，Worker 在五分钟更新周期内分批重算这些日报。单次重算只读取当天及判定低负载所需的相邻区间。
- 跨午夜的持续低负载可以回写到前一天。保留至少 15 分钟的前后采样上下文，并考虑采样区间的边界。已有价格、缺价、缺监控、有效零值和空转成本的计算口径沿用现有规则。

## 回填与同步

- 首次上线分批从保留的原始区间补齐最近 30 天。回填期间，缺少日报的查询可用已有计算路径提供数据。
- 补录费率时，在保存事务中把该实例对应生效区间内需要补价的日期加入优先队列。Worker 优先重算这些日期。待处理记录持久化，重启后继续。
- Worker 在读事务中计算，之后在短写事务内核对任务版本，再发布日报并移除待处理记录。计算期间进入的新采样或费率变更会保留待处理状态。恢复旧备份时清除派生数据，按恢复后的原始记录重建。

## 页面与接口

- 看板和实例详情共用日报，显示「数据截至」和待更新状态。常规轮询只读取数值汇总；展开低负载时段或开机等待时，再按需读取连续时段明细。
- 既有 API 和 MCP 调用继续返回原有字段。页面用可选参数请求轻量汇总。保留原始区间供明细读取、核对和费率补算。

## 库存趋势与其他计算

- 平台余量和关注规格共用资源池小时统计。保存各余卡数出现次数，查询时按卡数门槛统计并从分布计算中位数。滚动七天窗口首尾的非整小时仍按精确采样时间读取。
- 目录状态按小时保存已知和可用样本数。库存采集、同一采样槽覆盖、过期清理和旧库回填都同步维护小时统计。租卡提醒复用小时统计。
- 「我的用量」沿用已有采集时写入的用量日报。开机等待、低负载时段明细和自定义占卡试算保留精确时序查询，分别在展开明细和提交试算时计算。

## 验收

- 比较既有计算与日报的今日、近 7 天、近 30 天和单实例结果，覆盖跨午夜、补录费率边界、0% 与未知金额。
- 验证补算批次、进程中断重试、并发失效和数据库恢复。用约 43,200 条模拟区间比较汇总耗时，并确认日报齐备后数值请求不访问原始区间表。
- 验证前端两处入口和按需明细，使用隔离镜像确认 Worker 回填及旧镜像可读，再上线。
