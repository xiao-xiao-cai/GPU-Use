# 外部写入与恢复评审

**读取条件** 改动涉及异步写入、重复触发、计费申请、取消、恢复备份或操作归属。

1. 确定请求标识、项目和目标对象。任务触发时保存约束快照，使模板后来修改时已入队的运行仍能使用原条件。
2. 先持久化操作意图和需要的预留，再调用外部系统。将每种返回归为明确成功、明确拒绝、结果不明。为每类记录可用于后续查询的证据。
3. 客户端、SDK 和任务调度器的重试策略要一起检查。对结果不明的非幂等写操作，保持占位并回读。一次空查询、缺页或窗口截止均不足以证明外部没有成功。
4. 在返回成功前明确终态的依据。对云端预约记录目标实例、目标时刻与回读结果，撤销前比对当前归属。外部已改期时保留冲突供处理。
5. 分开处理正常重启与旧备份恢复。验收至少覆盖两种情况。一是云端已受理请求但本地尚未记下回执，二是云端已经完成购买而数据库还原到了购买之前。核对云端实例、订单与任务标识，确认恢复后的调度器不会重放同一笔购买。
6. 对提交通知的事件使用独立投递记录。模拟“通知失败并重试”，核对外部业务请求的发送次数保持不变。
